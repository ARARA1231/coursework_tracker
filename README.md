# Учёт курсовых работ

## Назначение

Приложение для учёта курсовых работ. Оно помогает отслеживать, какой
студент выполняет курсовую работу, кто является её руководителем,
на каком этапе находится работа и сколько времени осталось до срока сдачи.

## Целевая аудитория

- преподаватели — руководители курсовых работ;
- студенты, выполняющие курсовые работы;
- сотрудники учебного отдела.

## Предметная область

Студент выполняет курсовую работу под руководством преподавателя.
У работы есть тема, срок сдачи, статус и оценка.

Правила предметной области:

- работа проходит этапы «в работе» → «на проверке» → «защищена»;
- работу на проверке можно вернуть на доработку;
- оценка (от 2 до 5) выставляется только при защите;
- у студента может быть только одна активная (не защищённая) работа;
- преподаватель руководит ограниченным числом студентов (`max_students`),
  защищённые работы место не занимают.

## Основные сущности

| Класс        | Атрибуты                                                   | Поведение                                              |
|--------------|------------------------------------------------------------|--------------------------------------------------------|
| `Student`    | id, name, group, email                                     | строковое представление                                |
| `Teacher`    | id, name, department, email, max_students                  | `has_free_slots()`, `free_slots()`                     |
| `Coursework` | id, title, student, teacher, deadline, status, grade       | `submit()`, `return_to_work()`, `defend()`, `days_left()`, `is_active`, `is_overdue` |

`Coursework` хранит ссылки на объекты `Student` и `Teacher`, а в JSON
сохраняются их идентификаторы `student_id` и `teacher_id`.

## Основные функции

- просмотр студентов, преподавателей и курсовых работ;
- проверка, может ли преподаватель взять ещё одного студента;
- создание курсовой работы с проверкой правил;
- смена статуса: сдача на проверку, возврат, защита с оценкой;
- расчёт дней до срока сдачи и предупреждение о просрочке;
- фильтрация работ по статусу и сортировка по сроку сдачи.

## Веб-интерфейс (Django)

| Адрес                  | Страница                                         |
|------------------------|--------------------------------------------------|
| `/`                    | главная: описание системы и разделы              |
| `/courseworks/`        | список работ по сроку сдачи                      |
| `/courseworks/<id>/`   | работа: студент, руководитель, срок, статус, оценка |
| `/students/`           | список студентов                                 |
| `/students/<id>/`      | студент и его курсовая работа                    |
| `/teachers/`           | преподаватели и свободные места                  |
| `/teachers/<id>/`      | преподаватель, занятость, работы под руководством |

Несуществующий объект (например, `/courseworks/9999/`) показывает
страницу «не найдено» с кодом ответа 404.

Реализовано на шаблонах Django (Django Template Language):

- базовый шаблон `base.html` с блоками `title` и `content`;
- наследование шаблонов через `{% extends %}`;
- повторяющиеся части через `{% include %}`: навигация, карточки,
  статус курсовой работы;
- view-функции передают данные через контекст и `render()`;
- циклы `{% for %}` с `{% empty %}`, условия `{% if %}` / `{% elif %}`;
- ссылки через `{% url %}` и именованные маршруты (`app_name`);
- фильтры `length`, `default`, `date`;
- статические файлы: собственный CSS, JavaScript (год в подвале), логотип.

Данные пока хранятся в JSON. Django ORM, база данных и формы будут
подключены на следующих этапах.

## База данных SQLite (ПР7)

Данные перенесены из JSON в базу `data/coursetrack.sqlite`.
JSON-файлы остаются исходными данными для импорта и консольного меню.

### Таблицы

| Таблица | Поля |
|---|---|
| students | id INTEGER PK, name TEXT, group_name TEXT, email TEXT |
| teachers | id INTEGER PK, name TEXT, department TEXT, email TEXT, max_students INTEGER |
| courseworks | id INTEGER PK, title TEXT, student_id INTEGER FK → students.id, teacher_id INTEGER FK → teachers.id, deadline TEXT (YYYY-MM-DD), status TEXT, grade INTEGER (NULL до защиты) |

### Файлы

- `sql/schema.sql` — создание таблиц (PRIMARY KEY, FOREIGN KEY, NOT NULL, DEFAULT);
- `sql/queries.sql` — 12 проверенных запросов: выборки списков, WHERE, JOIN, COUNT/SUM/AVG, GROUP BY, HAVING;
- `db/database.py` — подключение: `PRAGMA foreign_keys = ON`, `row_factory = sqlite3.Row`;
- `db/import_json.py` — создание схемы и перенос данных из JSON (можно запускать повторно);
- `db/queries.py` — запросы, которые выполняют Django-представления.

Пересоздать базу:

```text
python -m db.import_json
```

### Страницы, работающие с базой

- `/courseworks/active/` — активные работы со студентом и руководителем (JOIN);
- `/courseworks/by-status/` — работы с выбранным статусом (WHERE с параметром);
- `/teachers/free/` — поиск руководителя со свободными местами по кафедре (LEFT JOIN, GROUP BY, HAVING);
- `/courseworks/statistics/` — статистика: всего, защищено, средняя оценка, по статусам, нагрузка преподавателей, студенты без работы.

На следующих практических работах база будет подключена через Django ORM.
